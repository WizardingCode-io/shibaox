# Fase 2A-2 — Painel Ink: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** um painel interativo de terminal (`shibaox` sem argumentos) que lista runs, mostra o stream do run selecionado, responde ao inbox e lança runs novos, como cliente puro da API do daemon; `run`/`follow` com TTY usam o mesmo stream.

**Architecture:** novo pacote `apps/tui` (Ink 7 + React 19). Um `AppStore` (estado + subscribers, sem Redux) alimentado por `poll.ts` (sondagem de `listRuns`/`inbox`/`health` e uma subscrição SSE do run selecionado) e por ações que chamam o `DaemonClient`. Componentes pequenos mapeados do design system (`AgentStatus`, `ToolCallLine`, `InboxBanner`, `Toast`, `Prompt`, `NewRunForm`) compostos em `Dashboard`. O CLI liga `shibaox`/`shibaox ui` ao `renderDashboard` e `run`/`follow` ao `renderStream` quando há TTY.

**Tech Stack:** TypeScript strict ESM/NodeNext (`jsx: react-jsx`), `ink@^7.1.1`, `react@^19.3.0`, `@types/react@^19`, `ink-testing-library@^4`, vitest, biome. Dependências de workspace: `@wizardingcode/shibaox-daemon` (tipos e `DaemonClient`), `@wizardingcode/shibaox-schemas` (`loadOrg`), `@wizardingcode/shibaox-core` (tipos).

**Spec:** `docs/superpowers/specs/2026-09-26-shibaox-2a2-tui-design.md`

## Global Constraints

- Node `>=22`; ESM com imports relativos `.js` (também para ficheiros `.tsx`); `pnpm build && pnpm test && pnpm lint` verdes (0 erros de lint; as 9 warnings `noNonNullAssertion` pré-existentes são aceites).
- Dependências novas permitidas: `ink@^7.1.1`, `react@^19.3.0`, `@types/react@^19`, `ink-testing-library@^4`. Nada mais.
- A TUI é cliente puro: nenhuma alteração ao daemon nem à API. Usa só o subconjunto `DaemonClientLike`.
- Sondagem: `listRuns` + `inbox` a 1 s (500 ms nos 3 s a seguir a uma ação), `health` a 5 s; falha → 5 s até recuperar. Uma subscrição SSE de cada vez. 2000 linhas de stream por run.
- Copy: sentence case, verbo-primeiro, sem emoji; palavras de estado `Working`, `Needs you`, `Queued`, `Done`, `Failed`, `Paused`, `Cancelled`. Estado nunca só por cor: sempre palavra ou símbolo.
- Tema (hex do tema dark): seleção/foco `#ffa15c`, sucesso `#6acb8e`, a correr `#86aef5`, atenção `#f2c150`, erro `#ff7a8a`, metadados `#b9a694`.
- `SHIBAOX_NO_MOTION=1` desliga animações (`Wave` fixo em `…`).
- Sem TTY: `shibaox` recusa com `The dashboard needs an interactive terminal. Try: shibaox runs` (exit 1); `run`/`follow` sem TTY ou com `--json` mantêm o texto atual. A TUI nunca escreve em modo `--json`.
- Testes limpam diretórios temporários e não deixam timers vivos (todos os `setInterval`/`setTimeout` são parados no `unmount`).
- Commits terminam com `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. **O daemon cai com o painel aberto.** A faixa `Daemon unreachable, retrying…` aparece, as teclas de ação não fazem chamadas, e quando o daemon volta a lista atualiza e a subscrição SSE do run selecionado é reaberta. Teste na Task 3 (`recovers after the daemon comes back and reopens the stream`).
2. **Dois pedidos no inbox e o primeiro é respondido pelo Telegram enquanto o painel mostra a faixa.** `a` no painel recebe 409, mostra `Already answered elsewhere`, e a faixa passa ao pedido seguinte na sondagem seguinte. Teste na Task 5 (`a 409 shows a toast and the banner moves on`).
3. **Trocar de run rapidamente (`j` várias vezes).** Só o último run tem subscrição aberta; frames de subscrições abortadas não aparecem no run errado. Teste na Task 3 (`switching runs quickly keeps a single subscription`).
4. **Um run com mais de 2000 linhas de stream.** As mais antigas caem, o painel continua a responder e o auto-scroll mostra o fim. Teste na Task 2 (`stream keeps the last 2000 lines`).
5. **Formulário com um org que não carrega.** O erro do `loadOrg` aparece junto ao campo, o `enter` não submete, e corrigir o caminho recarrega os workflows. Teste na Task 6 (`an invalid org shows the load error and blocks submit`).

export interface ToolInfo { id?: string; name: string; summary: string; status: 'running' | 'done' | 'error' | 'approval'; durationMs?: number }
export interface StreamLine { kind: 'text' | 'tool' | 'session' | 'event'; nodeId: string; depth: 0 | 1; text: string; tool?: ToolInfo }
/** Applies one SSE frame to the run's lines (immutable); returns the new array. */
export function applyFrame(lines: readonly StreamLine[], env: Envelope): StreamLine[];
export const summarizeInput: (input: unknown) => string; // ≤ 80 chars, JSON
export const RUN_EVENT_REFRESH: ReadonlySet<string>; // NodeStarted, NodeCompleted, NodeFailed, GatePassed, GateFailed, HumanRequested, ToolApprovalRequested, NodeSuspended, BudgetExceeded, RunCompleted, RunCancelled

Regras: `text` → linha `text` (uma por `\n`, `depth 1` com `parentToolUseId`); `tool_use` → linha `tool` `running` (`summary = summarizeInput(input)`); `tool_result` com o mesmo `id` → a linha existente passa a `done` (ou `error` se `output` é `{ error }`) com `durationMs`; sem id conhecido → nova linha `done`; `session` → linha `session` `session <id>`; frames `run` `NodeStarted` → linha `event` `── <nodeId> ──`; `ToolApprovalRequested` → a última linha `tool` `Bash` do mesmo nó passa a `approval`; outros frames `run` não geram linhas.

**Files:**

- Consumes: `AppStore`, `applyFrame`, `RUN_EVENT_REFRESH`, `DaemonClientLike`.
- Produces:

```ts
export interface PollerOptions { client: DaemonClientLike; store: AppStore; now?: () => number; intervals?: { fast: number; normal: number; slow: number; health: number } } // defaults 500, 1000, 5000, 5000
export class Poller {
  constructor(o: PollerOptions);
  start(): void; stop(): void;               // stop aborts the SSE subscription and clears timers
  tick(): Promise<void>;                     // one listRuns+inbox round (tests call it directly)
  healthTick(): Promise<void>;
  answer(id: string, approved: boolean, note?: string): Promise<void>;   // toast success/danger; 409 → 'Already answered elsewhere'
  cancel(runId: string): Promise<void>; resume(runId: string, budgetUsd?: number): Promise<void>;
  submit(req: SubmitRequest): Promise<string | undefined>;              // returns runId, selects it
}
```

Regras: cada `tick` chama `listRuns()` e `inbox()`; sucesso → `setReachable(true)`, `setRuns`, `setInbox`; falha → `setReachable(false)`, próximo tick em `slow`. Depois de uma ação, os próximos 3 s usam `fast`. A subscrição SSE segue `store.get().selectedRunId`: quando muda, aborta a anterior (`AbortController`) e abre `client.events(runId)`; cada frame → `store.pushLines(runId, applyFrame(...))`; frames `run` em `RUN_EVENT_REFRESH` → `getRun` → `setRunState`; `end` → `getRun` final. Se o daemon estava inacessível e volta, a subscrição é reaberta com `since` = último cursor recebido. `actionsEnabled = daemonReachable`.

- [ ] **Step 1: Testes a falhar** com `FakeDaemonClient` e `vi.useFakeTimers()`:
  - `tick` preenche runs e inbox; `failing=true` → `daemonReachable=false` e o intervalo passa a `slow`; **Review Focus 1** (`recovers after the daemon comes back and reopens the stream`): com `failing=true` o stream do run selecionado é abortado (`openStreams()` vazio), `failing=false` + `tick` → reachable e `openStreams()` volta a conter o run.
  - **Review Focus 3** (`switching runs quickly keeps a single subscription`): `select('a')`, `select('b')`, `select('c')` em sequência → `openStreams()` é `['c']`; `pushFrame('a', …)` não altera `streams.a`... (a fake só entrega a iteradores vivos; verificar que `streams.c` recebe e `streams.a` fica vazio).
  - `answer` com `answerError 409` → toast `Already answered elsewhere` (tone `info`); com sucesso → toast `Approved`/`Denied`; `submit` seleciona o run devolvido; `stop()` deixa `openStreams()` vazio e sem timers (`vi.getTimerCount() === 0`).
- [ ] **Step 2–4:** ver falhar, implementar, ver passar. **Step 5: Commit** `feat(tui): poller with backoff, single stream subscription and actions`.
